How to Extract Audio from a Video on Mac (4 Methods, 2026)

You have a video file and you want just the sound — for a podcast clip, an edit, or transcription. There are four reliable ways to extract audio from video on a Mac, and the right one depends on what the file is and where the sound should end up.

This guide covers the one-line Terminal routes first (they are the fastest and the only truly lossless ones), then a free GUI, then the case no file-based tool solves: audio that only exists as live playback. The capture side of the job — recording what your Mac is playing — has its own hub guide, how to record audio on a Mac; this one is about files you already have.

How to extract audio from video on Mac: the short answer

  • Audio already in the file, you want it untouched → ffmpeg with stream copy (-c:a copy). No re-encoding, no quality change.
  • No extra installs allowed → macOS’s built-in afconvert in one line. Works with common movie files like .mp4; rejects .mkv.
  • You prefer clicking to typing → VLC’s Convert/Save dialog.
  • The audio only exists while it plays (a stream, a live call, an app that won’t export) → record your Mac’s system audio. AudioRecord does this in one click, straight to WAV or M4A.

Method 1: afconvert — already on your Mac, one line

macOS ships afconvert (Audio File Convert) with the system. It reads the audio track of a QuickTime-compatible movie file and writes a plain audio file:

afconvert -f m4af -d aac lecture.mp4 lecture.m4a
  • -f m4af picks the M4A container; -d aac the AAC data format.
  • Tested on this Mac (macOS 15.6): an .mp4 with AAC audio converts in under a second, and the output is a normal audio-only .m4a any player opens.
  • Limits, tested on the same Mac: it would not open an .mkv. If the source is a container macOS doesn’t natively read, use Method 2.
  • Read the full options with man afconvert.

Best for: common .mp4/.mov files, zero setup. (See it documented on any Mac with man afconvert — Apple doesn’t publish a web version.)

Method 2: ffmpeg — the lossless route

ffmpeg is the tool to reach for when you want the audio exactly as it is in the file, with no re-encode:

ffmpeg -i input.mp4 -vn -c:a copy output.m4a
  • -vn skips the video stream — the ffmpeg documentation describes -vn as skipping “inclusion of video, audio, subtitle and data streams” you don’t select, and here it applies to video.
  • -c:a copy copies the existing audio stream into the new container. Because the audio is never re-encoded, quality is bit-identical to the source track, and a 2-hour file extracts in seconds.
  • The output extension follows the source codec: AAC audio → .m4a. If the source codec doesn’t fit the container you name, either pick a matching one or re-encode:
ffmpeg -i input.mp4 -vn -c:a libmp3lame -q:a 4 output.mp3

Tested on this Mac with ffmpeg 8: both commands produced valid files (verified with afinfo — one audio track, correct duration, no video stream).

Best for: MKV and anything else ffmpeg reads, exact-quality extraction, batch jobs. Install via Homebrew (brew install ffmpeg).

Method 3: VLC — the free GUI route

If you’d rather not open Terminal, VLC (free, open source) converts a video’s audio track through its Convert/Save dialog: open the file, pick Convert, choose an audio profile such as “Audio - MP3”, set the destination, and start. VideoLAN’s own wiki documents the Convert/Save flow as the GUI way to transcode.

The trade-off versus Method 2: VLC’s profiles re-encode, so it is not a lossless path, and it is slower for long files. Best for: one-off jobs when you already use VLC.

Method 4: when there is no file — record system audio

Everything above assumes the sound is inside a file you can open. It often isn’t: a stream that won’t let you download, a live call, an app with no export. In that case the honest method is to capture what your Mac is playing while it plays.

FAQ

Does extracting audio reduce quality?

Only if something re-encodes it. ffmpeg’s stream copy never re-encodes — the bytes of the audio track are the same ones the video carried. GUI converters and MP3 exports re-encode by design, which costs a little quality in exchange for a format you need.

Should I extract to M4A or MP3?

Keep the original codec when you can: most .mp4 files carry AAC, so an .m4a copy is the faithful version. Produce an MP3 only when a player, editor, or upload form specifically requires it.

Can I extract audio from an MKV on a Mac?

Not with afconvert — tested on macOS 15.6, it refuses the file. ffmpeg reads MKV directly, and the same -vn -c:a copy pattern applies (name an output container that suits the audio codec, usually .m4a for AAC or .mka to keep any codec).

Can I grab audio from a stream instead of a file?

File-based tools only work on files. For anything that exists only as playback, record system audio (Method 4) — and record only content you have the rights to use.
